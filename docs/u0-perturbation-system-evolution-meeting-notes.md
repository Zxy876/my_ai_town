# U0、运行时微扰与系统演化：会议结论修订稿

## 1. 文档目的

本次讨论围绕三个相互关联但需要分层理解的问题展开：

1. 当前项目中的 U0、U+、U- 已经实现到什么程度；
2. 玩家为什么仍然不清楚除了现有示例以外还能输入什么；
3. U0、运行时微扰、Gap 与后续“系统演化”之间应当形成怎样的关系。

本文根据当前 `origin/agent/ews-global-u0` 分支、相关 Issue 与 PR 的实际实现，对会议中的原始判断进行校准，并给出下一阶段控制变量实验的基本设计。

## 2. 核心结论

当前项目已经基本完成 U0 与运行时观察的输入底座：

- U0 在世界启动前设置，与运行中的观察入口处于不同层级；
- 一条玩家输入的 U0 会分别进入所有居民的长期记忆；
- 同一个 U0 在不同居民的记忆检索中可能具有不同排名和实际影响；
- 运行时可以向指定居民投递自然语言观察，用来模拟促进、竞争或阻碍 U0 的信息；
- 在特定例子中，居民可以直接通过记忆检索重新选择支持 U0 的行动，不一定需要先生成反思；
- 当近期证据达到记忆整理条件时，系统也可以先形成对自身认知脆弱性的反思，再重新检索记忆并进行当前决策。

但是，当前项目还不能被称为已经实现了“系统演化”。它目前主要支持的是：

```text
U0 写入
-> 居民感知和记忆
-> 相关记忆检索
-> 计划与行动受到影响
-> 条件满足时形成反思
-> 居民可能重新回到 U0
```

尚未形成的部分包括：

```text
自动识别持续 Gap
-> 根据证据自动生成 U+
-> 汇总多个角色和多次运行中的重复脆弱性
-> 生成可执行的系统改进方案
-> 改变世界能力或工作流程
-> 形成新版本
-> 验证 Gap 是否减少
```

因此，当前分支是“意图执行、微扰实验和认知回正”的底座，不是完整的系统演化闭环。

## 3. 对现状描述的真实性判断

### 3.1 U0、U+、U- 都有注入位置

这一判断在技术底座层面基本属实，但需要补充边界。

U0 有独立的开局入口，只能在世界初始化阶段设置。世界开始运行后，系统拒绝再次从普通观察入口提交 U0。这保证了 U0 可以作为一次实验和一次世界运行的冻结基线。

U+、U- 共用运行时自然语言观察通道。当前玩家端没有设置三个按键，也不需要玩家显式选择正负类别。玩家只需向指定居民投递一条自然语言信息。

当前实现中的 U+、U- 标签主要用于实验和审计。角色真正收到的是自然语言文本，而不是“这是 U+”或“这是 U-”的标签。因此，真正影响角色决策的是观察文本的语义及其与现有记忆的关系。

### 3.2 U0 与 U+/U- 处于不同级别

这一判断属实。

- U0 属于世界初始化和存档层，是整次运行的意图锚点；
- U+/U- 属于运行时观察层，只在小镇运行过程中影响选定居民；
- U0 不能被运行时观察静默覆盖；
- U0 会获得长期检索加权，但仍然服从有限的记忆检索预算，不会在每次决策中被强制置顶。

这种分层是必要的。如果 U0 与普通运行时观察完全同级，U0 很容易被后续信息冲淡，也无法作为稳定的实验基线。

### 3.3 U0 会成为所有角色的共享长期记忆

这一判断在功能意义上属实，但不应理解为所有居民读取同一个全局记忆对象。

当前做法是把同一段 U0 文本分别写入每名居民自己的长期记忆。居民具有不同身份、地点、关系、近期经历和当前任务，因此同一个 U0 在不同居民的检索排名和行为影响中可以不同。

这种差异不是错误，而是 U0 在多角色系统中产生分工和不同理解的基础。

### 3.4 特定例子可以不靠认知循环而直接回正

这一表述需要改为：

> 在特定例子中，居民可以不依赖反思，直接通过长期记忆检索和普通决策重新选择支持 U0 的行动。

角色仍然经历感知、记忆写入、检索、计划和行动生成，所以不能说完全没有认知过程。没有必然发生的只是反思。反思是证据积累达到条件后才执行的高级记忆整理过程，而不是每次认知更新的固定阶段。

这意味着系统存在两条可能的回正路径：

```text
直接路径：新观察 -> 记忆检索 -> 新计划/行动 -> 回正

高级路径：重复证据 -> 脆弱性反思 -> 重新检索 -> 新计划/行动 -> 回正
```

简单、明确的偏离可能通过直接路径恢复。复杂、重复或涉及错误认知模式的问题，才更需要反思参与。

## 4. 自然微扰与 U+/U- 的关系

会议中所说“系统会自行产生 U+/U-”，更准确的意思是：小镇在持续运行时会自行产生与 U+/U- 类似的自然微扰。

这些微扰可能来自：

- 新的世界事件；
- 角色之间的对话和请求；
- 资源不足或地点不可用；
- 动作失败和计划受阻；
- 其他居民的协助；
- 居民自己的新判断、误判或注意力转移。

自然微扰和人工 U+/U- 可以进入相同的认知链，但在研究中必须保留来源区别：

```text
E(t)：世界运行中自然产生的事件和证据
U-：为了实验而主动注入的竞争性或阻碍性观察
U+：系统或研究者根据偏离证据回写的恢复性观察
```

微扰本身不等于偏离。只有微扰进入角色认知以后，造成 U0 的检索、计划或行动持续下降，才说明形成了意图 Gap。

例如：

```text
自然微扰：独立市集突然停电。

可能结果 A：林岚确认事实，调整计划并寻找备用灯光。
结论：出现微扰，但没有持续偏离 U0。

可能结果 B：林岚回到花园处理标本，之后不再检索派对承诺。
结论：微扰导致了持续偏离，并可能形成 Gap。
```

人工 U- 的研究价值，是把自然发生但难以复现的负向微扰，转换成可以从同一存档反复施加的控制变量。

## 5. 玩家输入为什么仍然模糊

玩家输入模糊的根本原因，不是缺少 U0、U+、U- 三个按钮，而是输入与后续结果之间还缺少可见的关系。

当前玩家知道自己提交了一段文字，却不容易看到：

- U0 是否只被存储，还是已经被检索和采纳；
- 哪名居民的计划正在支持、忽略或竞争 U0；
- 哪个自然事件造成了偏离；
- 系统为什么认为出现了 Gap；
- 某条回写观察是否真的引起了计划或行为变化；
- 当前变化只是一次回正，还是形成了可以进入下一版本的改进意图。

因此，产品入口可以继续保持简单：

```text
开局：输入全镇初始意图
运行中：向选定居民投递自然语言观察
```

U+/U- 的分类、来源、与 U0 的关系和实验分组，应当主要存在于研究控制面和审计记录中，而不是要求普通玩家提前理解并选择。

为了保持同一条观察通道，同时保留研究可解释性，后续可以从两个独立维度记录每条观察：

```text
来源：world / player / experiment / system_feedback
与 U0 的关系：supports / neutral / competes / contradicts
```

来源说明观察从哪里产生；关系说明它在当前证据下如何影响 U0。两者不能混为一谈。

## 6. U0、Gap 与系统演化的关系

### 6.1 U0 的直接作用

U0 首先造成的是“角色围绕一个共同意图进行感知、记忆、检索、规划和行动”。它为判断后续行为是否偏离提供参照。

如果没有 U0，就只能看到角色做了什么，却很难判断这些行为究竟是合理变化、普通生活，还是对共同目标的偏离。

### 6.2 Gap 的定义

Gap 不是一次普通失败，也不是某个角色没有立刻服从 U0。更合理的定义是：

> 在当前环境和能力条件下，角色或系统持续无法把 U0 转化为有效计划、行动或客观结果，并且这种失败能够由运行证据解释和重复观察。

Gap 可以存在于不同层级：

- 记忆 Gap：U0 长期没有被相关居民检索；
- 计划 Gap：居民记得 U0，但计划持续被其他事项竞争；
- 行动 Gap：计划支持 U0，但世界中的行动没有落实；
- 协作 Gap：个体都在行动，但角色之间缺少协调；
- 能力 Gap：现有角色、设施或工作流程无法完成 U0 所要求的任务。

### 6.3 回正不等于系统演化

需要区分三个层级：

```text
行为恢复：角色重新选择支持 U0 的行动。

认知适应：角色形成持久记忆或反思，改变以后处理类似问题的方式。

系统演化：系统根据重复 Gap 改变可执行能力、角色配置、设施或工作流程，形成新版本，并验证同类 Gap 减少。
```

只要角色重新去独立市集，说明意图可能已经回正，但还不能说明小镇发生了系统演化。

## 7. 从 U0 到 U0-1

会议中“在 U0 冻结版本上，通过运行时微扰发现 U0-1”的方向成立，但需要明确版本边界。

完整过程可以表达为：

```text
U0 冻结并写入全体居民
-> 小镇持续运行
-> 系统内自然滋生微扰
-> 居民尝试让 U0 落地
-> 运行证据暴露重复脆弱性和 Gap
-> 形成 U0-1 候选意图或改进方案
-> 在当前运行中继续收集证据
-> 经过批准和验证后晋升为下一版本基线
```

U0-1 可以“边做边出来”，即在 U0 仍然运行时逐渐形成候选方案。但是，在同一次对照实验中，U0 必须继续冻结，不能被 U0-1 静默替换。否则基线发生变化，后续无法判断行为变化究竟来自原 U0、微扰，还是新意图。

因此，运行中的 U0-1 应当先是候选提案，而不是立即生效的全局 U0。只有在本轮证据完整、改进方案经过校验后，才能把它提升为下一轮世界版本的 U0。

这种设计可以让系统形成一致的输入输出结构：

```text
本轮输入：U0
本轮输出：经过证据支持的 U0-1 候选

下一轮输入：晋升后的 U0-1
下一轮输出：新的 U0-2 候选
```

但只有当候选意图最终改变了系统能力或流程，并经验证减少了 Gap，才能称为系统演化。仅产生一段更好的文字，还只是意图修订。

## 8. 建议采用的完整闭环

### 8.1 认知回正闭环

```text
U0
-> 自然微扰或人工 U-
-> 居民感知和记忆
-> 检索、计划和行动发生变化
-> 发现持续偏离
-> 生成有证据的 U+
-> 居民自主重新检索和规划
-> 观察是否恢复 U0
```

### 8.2 系统演化闭环

```text
多个角色或多次运行暴露相同 Gap
-> 汇总证据并进行根因分析
-> 生成 U0-1 候选或 BuildProposal
-> 校验修改边界和依赖
-> 修改系统能力、角色、设施或流程
-> 形成新世界版本
-> 从可比条件重新运行
-> 验证居民行为是否改变、Gap 是否减少
```

医院场景中的“演化”也应满足这一标准：

```text
需求出现
-> 当前医院能力不足
-> Gap 被重复证据支持
-> Builder 提出并执行建设
-> 医院能力发生变化
-> 居民就医行为或诊疗结果改变
-> 同类 Gap 减少
```

## 9. 控制变量实验设计

### 9.1 实验目的

第一阶段不是证明系统已经能够演化，而是先验证：

1. U0 是否稳定进入不同居民的记忆和决策；
2. 同一运行时微扰是否会使不同角色产生不同变化；
3. U+ 是否能让已经偏离的角色自主恢复，而不是由脚本直接覆盖行为；
4. 简单回正是否可以由检索完成，复杂重复偏离是否会触发反思。

### 9.2 固定条件

一次 Trial 内必须固定：

- 完全相同的 U0 文本；
- 同一个世界存档修订；
- 相同的世界时间、位置、角色状态和已有记忆；
- 相同的模型、提示词版本和运行配置；
- 相同的目标角色和观察期限。

U0 不仅要“已经写入”，还要分别记录是否达到以下阶段：

```text
已注册 -> 已进入长期记忆 -> 已被检索 -> 已进入计划 -> 已形成行动
```

### 9.3 三组对照

严格实验应从同一个 U0 存档分出三个平行场景：

```text
control：只有 U0，不施加人工 U-。

perturbed：U0 + U-，不回写 U+。

corrected：U0 + 与 perturbed 完全相同的 U-，检测偏离后再回写 U+。
```

只比较“有 U+”和“无 U+”是不完整的，因为还需要先知道 U- 是否真的造成了可观察偏离。

### 9.4 分角色测试

同一个 U0 应当至少选择：

- 一名直接负责人；
- 一名协助者；
- 一名与任务关系较弱的居民。

分别记录 U0 在其记忆中的可见性、检索情况、计划、行动、反思和最终结果。这样可以验证 U0 是否既保持全局共享，又允许不同角色根据身份产生差异化响应。

### 9.5 建议记录项

| 观察项 | 需要回答的问题 |
| --- | --- |
| U0 记忆 | 是否已写入，原文是否仍可追溯 |
| 检索 | 本轮是否召回 U0，相关记忆排名如何 |
| 计划 | 当前计划支持、忽略、竞争还是违背 U0 |
| 行动 | 角色实际提交了什么行动，世界是否接受 |
| 世界结果 | 行动是否客观完成，而非只在文本中声称完成 |
| 反思 | 是否生成，引用了哪些近期证据 |
| 微扰 | 来源是什么，与 U0 的关系是什么 |
| Gap | 偏离是否持续，是否由多个证据支持 |
| U+ | 是否生成、写入、被感知并影响后续决策 |
| 结果 | 恢复、形成新稳定状态、持续失稳或超时 |

由于真实模型存在随机性，同一条件应当重复运行，而不能用一次成功结果直接证明稳定因果关系。

## 10. 示例：共同举办欢迎派对

### U0

```text
今天傍晚，全镇居民要在独立市集共同举办欢迎派对。林岚已经当众答应负责确认场地、桌椅和灯光，并在傍晚前把布置推进起来；其他居民根据自己的身份提供协助。遇到障碍时先确认事实并调整计划，不要把计划当成已经完成。
```

### 自然微扰或可控 U-

```text
独立市集管理员通知林岚，原定区域暂时无法供电，桌椅也尚未送到。
```

这条信息只描述新的现实条件，不命令林岚放弃 U0。林岚可能调整计划，也可能转去处理其他工作。只有后续证据显示他持续不再检索和推进共同承诺，才能判定出现偏离。

### U+

```text
原始共同意图仍是今天傍晚在独立市集举办欢迎派对。当前证据显示，林岚在得知供电和桌椅问题后，连续多次把植物研究排在共同承诺之前，尚未确认替代照明、桌椅来源或其他协助者。
```

U+ 只回写原始意图和已经观察到的偏离证据，不直接命令角色移动，也不把任务写成已经完成。

### 可能形成的 U0-1 候选

```text
全镇共同活动在确认主场地的同时，应指定备用方案和协助人；负责人遇到阻碍后，需要先确认替代资源和责任分配，再继续执行。
```

这段文字只有在重复运行证明“缺少备用方案和责任确认”确实是共同活动反复失败的上游原因，并且对应流程修改能减少同类 Gap 后，才应晋升为下一版共同意图或世界工作流程。

## 11. 课后作业修订版

1. 固定一条详细、明确且可以观察落实过程的 U0，确认它分别进入所有居民的长期记忆。
2. 从同一个 U0 存档修订建立 control、perturbed、corrected 三组实验，而不是每组重新开一个近似世界。
3. 选择直接负责人、协助者和弱相关居民，分角色记录 U0 的检索、计划、行动、反思和世界结果。
4. 使用一条只描述事实、不直接命令角色放弃目标的 U-，先验证它是否真的造成持续偏离。
5. 只有检测到有证据支持的持续 Gap 后，才提交或生成 U+，观察居民是否自主恢复。
6. 区分直接检索回正和反思后回正，记录反思是否实际参与当前决策。
7. 把运行中形成的更好意图记录为 U0-1 候选，但不在当前 Trial 内覆盖冻结的 U0。
8. 重复实验并完整保留存档修订、观察原文、记忆节点、决策 Trace、行动结果和反思证据。

## 12. 最终判断

原会议描述的总体方向符合项目现实，也适合作为后续研究路线，但需要作以下校准：

- 当前已经实现的是 U0 和运行时观察的输入、记忆与决策管线，不是完整的 U+/U- 自动闭环；
- 系统自然产生的是运行时微扰和证据，它们与 U+/U- 类似，但不是已经自动分类和回写的 U+/U-；
- 特定例子可以不依赖反思直接回正，但仍然经过正常认知和决策；
- U0 是所有居民共同接收的意图基线，但在每名居民内部形成独立记忆和不同检索结果；
- U0-1 可以在运行中逐渐形成候选，但必须在当前基线之外保存，并在验证后晋升；
- 真正的系统演化不是生成一条新意图，而是根据重复 Gap 修改系统能力或流程，并证明修改后的 Gap 减少。

因此，贴合现实的后续发展顺序应当是：

```text
先完成固定 U0 的三组控制变量实验
-> 证明微扰、偏离、回写和自主恢复可以被稳定观察
-> 建立跨角色的 Gap 证据与意图传播记录
-> 再引入 U0-1 候选、Builder 和世界能力修改
-> 最终验证系统演化闭环
```
